## 背景

需要降低提交的变更范围，使每次提交便于理解、验证、回滚和代码审查。

## 目标

将原子提交要求写入项目 README，作为所有贡献者共同遵循的提交规范。

## 范围

更新 README 的提交规范，不修改 Git 历史、Git Hook 或现有代码。

## 角色与术语

- 原子提交：只包含一个独立、可描述的功能或修复的 commit。

## 需求详细说明

### REQ-001

- 名称：单功能提交。
- 规则：每个 commit 必须只包含一个独立、可描述的功能或修复；禁止将多个功能、无关重构、依赖升级或格式化混入同一次提交。提交前必须只暂存关联文件，并确认暂存内容可以独立构建和验证。
- 验收：README 明确记录上述规则和多项并行工作应分别验证、分别提交的要求。

## 验收标准

- [x] REQ-001：README 已包含单功能、相关暂存和分别验证后提交的规范。

## 非功能要求

规则应简短、清晰，并适用于前后端代码。

## 不在范围内

- 修改既有提交历史。
- 增加自动拦截非原子提交的 Git Hook。
